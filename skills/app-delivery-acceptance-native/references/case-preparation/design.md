# 自然语言用例设计

从需求基线、当前测试场景和项目测试约定出发。逐项反查场景的验收判据和原始依据，将每条必测判据落实到具体检查或记录缺口，为各项检查给稳定 ID。发现需求行为遗漏或依据冲突时，指出原文及影响，交回场景阶段。既有代码的范围只能用于后续匹配，不能缩小设计范围。

把需要独立执行、取证和判定的验证目标各写成一个用例，在设计时给每个用例确定唯一的 `TC-...` ID。每个用例用自然语言写清业务标题、前置条件及数据、操作与输入、可核对的预期结果。人工项写到人能照做。一个用例可包含共同支撑同一判定的多个检查，也可用多个输入样本验证同一行为。多个用例可以共享测试文件和夹具。为未设计的检查记录具体原因。

从原始依据推导预期的业务值和比较对象。原始依据规定结果应匹配某个独立预期值时，在各个适用的观察面上分别断言。原始依据规定两个结果一致时，先确认找到本次操作对应的目标，再按规定比较这两个结果。额外观察单列，发现必测判据没有原始依据时交回场景阶段。

用 [操作工具](../../scripts/operations.mts) 的 `case-design <AT-ID>` 交付设计。用 `records show` 返回的 `definitions.sha256` 填 `definitions_sha256`，从同一收据的 `definitions.path` 读取场景记录。组装 JSON 时直接从记录取 `scenario_scope.criteria` 或各组 `groups[].criteria` 的字符串作为 `obligations[].quote`，需要引用片段时也从该字符串截取；旧场景未单列判据时取记录的 `source.text`。逐组核对覆盖，同一判据可支撑不同输入变体。只设计时读回收据，交付位置、已设计和未覆盖的范围后停止。

```json
{
  "request_id": "design-v1",
  "scene": "SC1",
  "definitions_sha256": "<当前记录快照摘要>",
  "obligations": [{"id":"reject","quote":"部分重叠的预约返回 409。"}],
  "cases": {
    "TC-reject-overlap": {
      "title": "拒绝重叠预约",
      "kind": "automated",
      "preconditions": "空库中已有 A 室 10:00–11:00 的预约",
      "checks": [{"id":"reject","action":"向 A 室提交 10:30–11:30 的预约","expected":"响应 JSON status 为 409"}]
    }
  }
}
```

示例只展示一个检查。实际收据覆盖本轮的全部必测项。若某个检查暂时没有用例，仍列入 `obligations`，并在 `gaps` 中以其 ID 记录原因。设计修订用新的请求 ID，语义仍相同的用例和检查保留原 ID。沿用已确认的 TDD 用例时，在设计中使用原 TC ID。匹配、调试、正式执行和复审都使用设计中的同一个 TC ID。确需拆分或新增用例时先修订设计，说明原用例和检查的去向。

## 边界检查

对照需求基线和当前测试场景列出会改变验收判定的输入变体。每项记录关联条款、具体输入、预期状态及内容或副作用、对应的设计用例 ID。按变体分配检查项 ID。同一场景判据可支撑多个检查项。记录待核对的变体。

为每条必测判据选能区分正确行为和合理错误行为的输入。先从原始依据确定判据适用的目标、动作前状态和动作，再看当前样例实际观察了哪些组合。需求对符合条件的任意目标作出同一承诺时，检查只处理当前样例或只处理最先遇到的目标的实现能否通过。需求要求动作保留已有状态时，检查动作发生前已处于适用状态的目标，逐个核对动作后的观察。动作发生后才进入某状态的目标，只能证明其随后经历的行为。用作准备数据的目标只有被对应断言检查时才算覆盖。

反例只有指出了有明确依据的覆盖缺口才阻塞放行：该错误会违反原文中的必测承诺，且现有断言对缺失的目标或状态仍可全过。用最少的额外检查区分这个错误，或引用已有的等价断言并说明适用范围。样本数量和组合由要区分的错误决定。其他可能失败的输入按可选补测记录，预期沿用原始依据。超出依据的变体单列为范围疑问。

接口若明确要求拒绝客户端指定其他身份，检查客户端实际可发送的身份载体。查询参数和可发送的请求体分别验证，包括只读请求。高层客户端无法发送时，用能发出该请求的低层客户端核实。校验签名或地址时，分别检查每个约束字段，保留其他字段原值。对标识字段分别检查改为另一个合法标识和改为超出合法取值域的值。必要时单独验证参数缺失。按验收依据原文分别断言状态码、返回数据及状态变化。依据冲突时记录出处，未执行的变体列为未覆盖并说明原因。
