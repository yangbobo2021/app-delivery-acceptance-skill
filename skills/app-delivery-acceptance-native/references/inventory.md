# 维护期交付盘点

从用户指定位置及项目 README 找需求、交付清单、既有测试和证据。固定本次盘点的 Git HEAD，检查实际工作区是否有变化。对历史收据同时核对当时版本、与当前相关的产品和测试文件摘要及原始执行日志。范围可复核且绑定文件字节一致的证据，可以支撑对应的当前结论，即使当前提交后来添加了归档文件。相关绑定变化、证据缺失或适用范围不明时，列为待复验或待确认。

已确认需求和代码、旧提交、讨论中推导的候选分开记录。仅凭静态阅读发现的实现差异写入风险说明。已有用例、缺少适用执行证据时用 `untested`，仅有不适用历史时用 `recheck`。`failed` 需要能归属当前版本的真实失败执行或观察证据。依据读取不到或互相冲突时，引用已找到的来源，写出要确认的问题。盘点本身使用只读查询。用户明确授权复验时才运行指定的已有检查，保留本轮退出码、原始输出、运行命令和版本依据，只更新受影响项。默认把报告和新日志写在 Git 已忽略的 `.acceptance-local/native-v1/`；用户给出输出位置时按该位置交付。

结构化报告可用 `{"revision":"当前完整 Git HEAD","items":[{"id":"需求 ID","status":"verified","sources":["实际依据路径"],"evidence":["实际收据或日志路径"],"next":"下一步或已交付说明"}]}`。状态使用 `verified`、`failed`、`recheck`、`untested`、`unconfirmed`、`source_missing`、`conflict` 或 `blocked`。每项给出适用范围和实际原因，复验项另写实际命令及退出码。交付报告后按授权停止。
