# 结果展示

用 [结果工具](../../scripts/results.py) 读取已有证据。查看是只读操作；报告将实际快照及所引用的证据字节放到同一本机导出目录。需要共享时，由用户明确选定可归档的内容。

```sh
python3 "<结果工具>" --root "<项目>" view "<AT-ID>"
python3 "<结果工具>" --root "<项目>" report "<AT-ID>" <<'JSON'
{"request_id":"report-sc1","scene_ids":["SC1"]}
JSON
```

查看旧项目的原始定义可用 [依据与定义](../definitions/entry.md) 的只读入口。报告链接指向实际生成的 `report.html` 与 `snapshot.json`。区分未执行、待独立复审、原证据缺失、旧版、产品缺陷、需修订和通过。只跑部分用例时交付该范围；场景通过需要全部必要义务、当前版本和对应独立证据。只查看或报告任务结束于交付链接。

用户要在浏览器持续查看时，可运行 `results.py --root <项目> serve <AT-ID>`，给出该进程实际返回的本机 URL。看板每 5 秒读取已落盘记录，按需求分组，每个场景占一行，并显示用例、实际执行和独立复审。一个场景关联多条需求时，各组都可跳转到同一份记录。搜索和状态筛选保留关联对象。点对象进入详情，可沿关系跳转和返回。更新时保留打开的详情，用户可以按提示更新。需要可分享的离线副本时使用报告导出。

用 TDD 验收 ID 打开看板时，执行列标记红灯或绿灯，独立结论显示预期红灯确认或绿灯复审。绿灯结果以 TDD 结论展示。

需求级状态取决于范围核对和所有关联场景。场景下分别显示自动用例与人工验证项。打开验证项的「关联关系」可访问同一 ID 的多次执行。每次执行的详情保留版本、文件摘要、实际结果、自己的证据和独立复审。当前结果随最新适用收据更新，历史执行仍可访问。

同一个 ID 跨阶段沿用时，TDD 用 `serve <AT-ID> --phase development`，正式验收用 `serve <AT-ID> --phase acceptance`。正式验收看板只用本阶段收据判断运行与通过状态。

维护盘点使用 `results.py --root <项目> serve-inventory`。看板在场景后列出关联用例及源码位置，并分别显示执行证据、交付状态和下一步。旧报告缺少 `cases` 时显示「未记录用例关联」。看板等待实际的 `.acceptance-local/native-v1/inventory.json` 落盘。

## 截图与落盘核对

每步先完成实际操作，重新读回落盘数据核对，再在看板或当前操作界面截图。用递增序号、需求 ID 或场景 ID、步骤名保存图片。共享的原始冻结、场景来源沿用核验和最终交付各保存一张。每条需求的缺口结论以及每个场景的匹配、准备、运行、复审或阻塞都要有各自的记录，适用几步就留下几步。

同目录保存 `checkpoints.json`，逐步记录 `step`、`requirement_id` 或 `scene_id`、定义摘要、实际数据位置、核对结论和截图相对路径。范围步骤核对冻结来源、需求与场景集合和新增 ID。场景步骤核对场景和用例 ID、当前版本，以及适用的命令、退出码、日志摘要或复审结论。盘点逐条核对落盘项、用例定位及历史证据适用性。看板等到本步数据已刷新后再截图。遇到阻塞也截图和记明原因。无截图能力时如实标记缺失。

进入下一条前核对当前条目已留下结论和证据。最后对照冻结清单，确认每条需求与每个场景都各有明确状态。被授权缩小范围时记录排除项及理由。
