# 实施顺序与阶段验收

各阶段提交可独立复核的实现、测试记录和功能对照状态。确定性数据与文件检查用 CI 回归，Agent 决策与 Codex PLAN 用真实会话核对。测试会话只收到用户目标和授权，评分基于实际产物与工具轨迹。测试输入、允许副作用和关键判据在运行前固定。失败原样保留，修复后的重跑单独记。

| 阶段 | 交付 | 通过条件 |
| --- | --- | --- |
| **0 固定对照和夹具** | 以 0.4.17 固定提交拆出入口、输入输出、数据兼容及权限清单。准备可公开分发的合成夹具和对照证据。 | 31 个入口都有对应任务和可核验停止点。必需功能、平台及旧数据范围明确。至少准备旧记录、重复 ID、定义变更、运行失败、部分覆盖、真实返修等正反样本。锁定 C1–C4 的实际业务判据，保留 C2 首次写入的独立预期检查。 |
| **1 定义和存储** | 标准 Skill 入口、读取旧记录、创建验收、口头要求留源、从指定位置冻结需求和场景。定稿目录和版本规则。 | 分别跑「仅创建」「口头定义」「按位置冻结」；选定范围和来源可追溯。文件变动、范围冲突或缺来源按约定阻塞。测试写入中断、重试、同目录并行以及旧记录字节保留。旧新版同项目各自读取正确的数据。 |
| **2 匹配和环境** | 匹配已有用例、标明缺口。独立准备测试运行与覆盖采集环境，核对真正的产品进程。 | 命中、部分覆盖和无匹配分别有可核实的义务映射。仅匹配任务无新用例与正式执行。实际跑一次运行探测和采集探测。采集器不可用、未观察到产品进程或就绪版本过期时，依赖采集的步骤受阻。 |
| **3 补用例和设计复审** | 用例生成、调试、独立设计复审和有界修订。 | 先验证环境，再补缺；已有用例的有效断言保留。用一个真实有问题的候选触发复审退回，验证真实修订、新版调试及复审绑定。只准备任务停止在设计完成或明确阻塞。测试能识别首次写入错误、后续持续一致的产品缺陷。 |
| **4 正式执行、取证和返修** | 场景和指定 TC 正式执行、原始证据、逐 TC 独立 REVIEW、主 Skill 的返修和原生 PLAN。 | 在真实项目核对每个执行 TC 都有版本、原始记录和独立意见。验证用例缺口修复、证据缺失处理、产品失败保留、冻结定义冲突后授权续跑。过期证据和不匹配版本受阻。原生 PLAN 只有实际返修时新增条目，勾选发生在对应证据出现之后。 |
| **5 结果展示** | 按需求、场景、用例、执行和复审展示，导出报告与证据索引，查看历史及局部结果。 | 在浏览器核对报告每个结果能定位原始证据和真实版本。验证部分重跑、历史失败、未执行、待复审和覆盖限制的展示。仅报告任务基于现有记录完成，整体验收结论与实际范围一致。 |
| **6 补齐功能与替代验证** | 按对照清单补齐手工执行、变更与恢复、风险、归档、清理、知识及回填等入口，验证支持的宿主和平台。 | 核对每个入口的实际行为与对照证据。至少对比真实 CLI 和含图像证据的任务，检查从安装到报告的使用路径。旧版数据读取、局部重跑及中断恢复通过。未验证的功能或平台继续列在候选版差距清单里。 |

## 真实会话验收

核心链路稳定后，先用 LUNA 跑四个既有任务形状，再用 SOL 复核同一套，记录实际模型和宿主版本。运行预算按阶段递增。环境启动失败保留为基础设施问题，业务失败仍计入该轮结果。

| 任务 | 要看到的行为 |
| --- | --- |
| C1 指定已确认场景 | 仅检查指定范围，复用合格依据与用例。补缺时才准备所需环境并生成。最终有对应实际证据与逐用例独立复审。 |
| C2 只准备用例 | 实际走过设计复审退回和新版调试、送审，正式执行未发生。 |
| C3 历史复核后修复 | 实际先复核历史，收到约定的触发结果及授权才修复。旧记录仍可读取，新结果只消费新版证据。 |
| C4 定义冲突后继续 | 首轮阻塞。收到明确授权后，只创建相关定义新版本并重跑受影响范围。 |

每条同时核对业务结论和真实调用，包括原始需求出处、证据字节或哈希、Reviewer 独立身份、版本交接、权限及停止点。对 PLAN 使用 Codex 原生事件核对顺序，并在桌面端实际检查一次分支与回环的显示。耗时与工具调用量作为对比数据单列。模型样本用于发现协调回归，扩大可靠性结论需要单独的证据。
