# 功能对照清单

主对照为原仓库 `main` 的固定提交 `525e92f29fe5c625a37669f701897596d04edfd6`，工作流包版本 0.4.17。此前 0.4.9 原生化实验的 C1–C4 可作为夹具来源，期望行为按主对照复核。以下列出固定提交中的全部 31 个已注册入口。入口名称用来定位旧行为，用户以自然语言提出同等业务任务。 [原版固定提交](https://github.com/yangbobo2021/app-delivery-acceptance/tree/525e92f29fe5c625a37669f701897596d04edfd6)

| 编号 | 原版入口 | 新版要交付的结果与停止点 | 阶段 |
| --- | --- | --- | --- |
| P01 | `create`、`freeze` | 仅创建的空验收，口头要求原话，按指定位置冻结需求和场景，按实际授权确定范围。冲突或缺失保留原材料。 | 1 |
| P02 | `current`、`start` | 查询或切换当前验收。当前身份明确，另一活动验收受到保护。 | 1、6 |
| P03 | `analyze`、`scenarios`、`assess-scenarios` | 需求分析、场景创建或修订、独立场景评估可分别停止。保留已有定义与未覆盖义务。 | 1、6 |
| P04 | `find-cases` | 仅匹配实际既有用例。返回逐用例贡献、部分覆盖及缺口。保留稳定 TC 身份，依据原版规则和用户授权处理 ID 注释等允许的最小元数据变化。 | 2 |
| P05 | `runtime`、`coverage`、`project` | 项目测试与覆盖环境可单独准备。交付真实可复用的就绪证据、版本绑定和工具限制。 | 2 |
| P06 | `cases`、`assess-cases` | 先匹配后补用例，环境就绪后才生成，实际调试并独立评估；只评估模式止于只读意见。 | 3 |
| P07 | `execute`、`manual-execute` | 场景执行和指定 TC 重跑留有真实证据和逐 TC 独立结论。手工模式冻结确已发生的动作及附件。修订保留新尝试和对应意见。 | 4、6 |
| P08 | `orchestrate` | 从用户目标选择范围和停止点。根据真实依赖和结果调整路线，支持补充授权后继续。原生 PLAN 显示本次工作和回环。 | 1–6 |
| P09 | `view`、`report`、`coverage-recompute` | 展示需求、场景、用例、执行、复审及历史；导出报告和快照；可仅基于已有原生覆盖数据重算统计。 | 5、6 |
| P10 | `delivery-judge`、`risk` | 核验完整选定需求或交付范围，记录用户接受的明确风险及依据，保留原技术结论。 | 5、6 |
| P11 | `reverse`、`change-plan`、`rebind`、`source-status` | 从提交或 PR 提取候选依据，判断变化影响、切换被测版本，区分源读取失败与确认删除。 | 6 |
| P12 | `recover`、`archive`、`finish`、`cleanup` | 查明中断及可能副作用，保全后恢复。选择性归档，结束对应验收，按明确授权清理指定资产。 | 6 |
| P13 | `knowledge`、`backfill` | 保存已验证的项目知识，按项目约定和授权将选定内容回填为可审查产物。 | 6 |

阶段 0 将每组细化为逐入口用例，记录固定来源、原版实际结果或合同依据、新版入口、允许副作用、停止点、验收证据和状态。普通通过、部分支持、阻塞、仅分析等各按任务目标评分。需要实跑的入口在真实对照完成前标为待验证。候选版本明确列出暂缺功能，完整替代须逐项验收。

需要独立验证的兼容项包括旧资料与证据可读性、同项目并行试用、原版支持的运行环境、只读查看和归档离线可读。原版安装器、旧命令入口及执行运行时的兼容范围在阶段 0 明确，供已有自动化使用者评估迁移。
